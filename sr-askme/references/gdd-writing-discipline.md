# GDD 撰写纪律（成稿 / 定稿共用）

`sr-gdd-human`（写成稿）、`sr-gdd-fix`（改定稿）与 `sr-gdd-ai`（首次整合）共用同一套撰写纪律。**本文件是它的唯一出处**——各 skill 只留指针与自查清单，不复制条文。`适用` 列写明每条纪律落在哪一侧，变体不同的在条文里分开写。

| 编号 | 纪律 | 判据 | 适用 |
| --- | --- | --- | --- |
| D1 | **规则写法**：每条规则一句话说清"谁在什么条件下做什么、得到什么、边界是什么"，条件/动作/结果/边界齐全；一个主题一个规则组，只编组级 R1、R2…，组内不编小号；交叉引用引到组级（如"见 R2"），确需指明组内某条时写"R2 存量不足"这类"组号+规则名" | 非策划/程序的人能一句话复述；规则章只有组级编号 | 两者 · 定稿沿用既有组号，新增规则挂进所属组，出现新主题才新增组号 |
| D2 | **规则里只写设计语言**：成稿零配置指代——字段名、表名、`snake_case`、"对应某个字段 / 落到某个配置项 / 写进 XX 表"式中文字都不出现；定稿的规则正文同样只写设计语言，配置对应只写在 §4 的「配置字段」列与 §6 配置契约里 | 成稿：全文搜不到配置指代；定稿：规则列与「配置字段」列各归各位 | 两者 · 变体不同 |
| D3 | **数值**：成稿写机制表述（"每 N 次""达到主城等级门槛""概率合计 100%"）+ 需落数处写"（参考值 X，待定）"，§11 只列待定项名称；定稿写实际落地 `表名.字段名`，未落表的标"待配表" | 成稿：把配置表数字任意改一遍，结果章一字不用改；定稿：每个数值都能在配置表里找到，或明确标"待配表" | 两者 · 变体不同 |
| D4 | **当前口径**：正文只写当前生效规则；被取代的旧口径在成稿收进 §12（一句话、不列表格、不做对比），定稿不放新旧对照——取代关系写进改动清单 | 正文无"曾经 / 原先 / 旧稿 / 变更前 / 本次已改"式表述 | 两者 |
| D5 | **界面章**：每个界面单独一张 ASCII 线框图（布局 + 控件 + UE 标注）+ 一张逐条编号的 UE 规则表；界面清单总览 + 流程 text 图 + 状态机（如适用）+ 全局交互规范；嵌套的解锁 / 失败分支 / 默认回退用层级缩进列表，不塞进大表格 | 每个界面都有线框图，注释单义、读不出第二种排版 | 两者 |
| D6 | **归属边界**：通用组件（如货币详情弹窗）与其它系统既有界面（如英雄详情页）在界面清单下声明"不属于本功能"，本功能只写触发关系 | 界面清单里每张图都能归属到本功能 | 两者 |
| D7 | **上游映射**：入口产出与旧案的每条设计结论落到对应章节——功能意图→§1；玩家动词→§2；核心循环→§3；功能详细→§4；界面/UE→§5；范围与不做项→§6；埋点→§7；验证计划（含**验证指标**与**测试后回写**）→§8；验收→§9；数值待定→§11；概念种子→A.2；设计核候选→A.3；玩家承诺→A.4；假设→A.5；风险→A.6；未决取舍→A.7；**不确定性校准→§4（随机性与概率类规则）+ §8（验证指标）**；迁移边界（sr-analysis 入口）→§4 规则 + §6 范围门。已拍板取舍直接成为规则口径，不重问、不写拍板过程；映射不了的差异写"待确认：<事项>"。§10 交接清单、§12 已废弃口径与 A.1 / A.8 / A.9 由成稿自产，不要求上游来源 | 上游每个设计结论在文中都有落点，不遗漏、不只在对话里提一句 | 仅成稿 |
| D8 | **证据纪律**（完整卡见 `evidence-boundary.md`）：证据优先级 `配置表 > 客户端代码 > 策划文档/UE > 推断`，材料冲突以高优先级来源为准、正文按胜出口径写；推断标 `【推断】`；市场 / 付费 / 增长类断言无证据不写入；缺材料时列最小缺失清单由人决定 | 每个推断有 `【推断】` 标记，无把未知写成确定事实 | 两者 · 定稿只用其中「轻量标注」一段 |
| D9 | **文本卫生**：术语全文一致（同一系统一个名字）；只留结构性留痕（表格、一句话条目），对话过程、中间草稿、被否掉的候选论证不进文档 | 术语无混用；无过程叙事 | 两者 |
| D10 | **附录 A 台账**：A.1–A.9 在成稿阶段随取舍同步填写（不事后补造）；无独立设计核取舍时 A.3 写"继承自上游"，不强凑 | 无占位符残留，与正文结论一致 | 仅成稿 |
| D11 | **影响面闭合**：改一处必须扫全受影响面——规则 ↔ 界面 UE ↔ 范围门 ↔ 埋点 ↔ 验收标准 ↔ §6 字段对应 ↔ §7 多语言文本；逐条列进改动清单，改完再核一遍 | 改动清单覆盖全部受影响章节；无"改了规则忘了验收 / 忘了字段"的漏改 | 仅定稿修改 |
