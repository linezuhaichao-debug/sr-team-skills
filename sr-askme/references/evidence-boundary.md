# 证据边界方法卡（共享）

策划案最危险的失败不是不完整，而是把未知写成确定事实。本卡由 sr 系列共用，**按需取用其中一段**：

- `sr-gdd-human`：用「来源标签」+「Evidence Ledger 格式」+「台账填写判据」+「高风险断言清单」填附录 A 的假设台账（A.5）与风险台账（A.6）。
- `sr-gdd-ai` / `sr-gdd-fix`：只用「轻量标注」四条做正文行内标注；来源标签与 Evidence Ledger 属于过程留痕，留在成稿，不入定稿。
- `sr-concept` / `sr-analysis`：其内嵌方法卡自带来源标签与高风险断言规则，**未挂本文件指针**；需要完整卡片时按需取用「来源标签」「台账填写判据」「高风险断言清单」「VOI 判断」。

## 来源标签（关键判断按此归类）

| 标签 | 含义 | 写法 |
| --- | --- | --- |
| `provided` | 用户明确提供 | 按用户材料复述，不额外扩大 |
| `derived` | 从已提供材料合理推导 | 标注推导链路 |
| `external_evidence` | 来自当前外部来源、公开数据、评论、商店页、报告 | 必须保留来源或引用位置 |
| `assumption` | 为了推进文档而作出的假设 | 写置信度、影响、验证方式 |
| `unknown` | 当前无法判断 | 写缺失信息和影响 |
| `needs_research` | 会改变关键决策，值得调研 | 写 VOI 和最小调研动作 |
| `not_run` | 当前未做外部调研，且 VOI 不足 | 写不做的理由 |

## Evidence Ledger 格式

| 判断 | 来源标签 | 证据/依据 | 置信度 | 影响等级 | 验证动作 |
| --- | --- | --- | --- | --- | --- |
| <关键判断> | assumption | <依据> | 中 | 高 | <最小验证动作> |

## 台账填写判据（假设 / 风险）

Evidence Ledger、成稿附录 A.5（假设台账）与 A.6（风险台账）共用下面这几张判据表——**不要各写一套**。

### 假设覆盖自检（不新增列，写完台账后逐项对照）

| 方面 | 典型假设 |
| --- | --- |
| 平台 | 假设目标是微信小游戏，而不是 Steam |
| 商业 | 假设依赖广告或 IAP，而不是买断 |
| 受众 | 假设面向轻度玩家或策略玩家 |
| 制作 | 假设团队能做物理手感、联网或 3D |
| 玩法 | 假设玩家喜欢某种风险取舍 |
| 内容 | 假设有足够关卡、角色或剧情产能 |

六个方面里凡是没有对应假设的，要显式写"已核，本功能不涉及"——**漏写与判定为不涉及，是两件事**。

### 置信度与影响等级（"置信度""影响"列写高/中/低时的判定标准）

| 等级 | 置信度 | 影响 |
| --- | --- | --- |
| 高 | 用户明确提供，或有强约束支持 | 错了会改变核心循环、平台、商业模式或 scope |
| 中 | 从创意和平台可合理推断 | 错了会影响系统优先级或验证方式 |
| 低 | 只是为了继续推演而临时设定 | 错了主要影响包装、命名或后续内容 |

### 风险处置动作（A.6"缓解动作"列按此取值）

风险**类型**以 `sr-gdd-human/resources/templates/feature-gdd-human.md` 的 A.6 枚举为准（生产/数值/体验/经济/技术/UI/文档——面向内部功能文档）。**缓解动作**取这五种之一：

| 动作 | 使用场景 |
| --- | --- |
| 验证 | 风险高但可通过小原型判断 |
| 降 scope | 有价值但当前成本过高 |
| 替代方案 | 保留承诺，换低成本系统 |
| 砍掉 | 不服务核心循环或验证代价过高 |
| 暂缓 | 依赖后续数据或团队能力 |

## 证据优先级

`配置表 > 客户端代码 > 策划文档/UE > 推断`。文档与配置/代码冲突时，以配置/代码为准，并把差异写入假设台账或待确认问题。

## 轻量标注（正文行内使用，与来源标签并用）

- 推断内容在正文标 `【推断】`，写成推断而非确定事实；
- 未定项写 `待确认：<事项>`，便于全文搜索；
- 引用真实配置 ID/数值/key 标 `[真实]`；教学或演示用示例值标 `[示例]`，示例值不冒充真实值。

## 高风险断言清单（没有证据时不写成确定结论）

- 市场已有需求或蓝海。
- 玩家一定会付费、看广告、分享或形成社区。
- 某品类正在增长、某平台有窗口、某渠道买量可行。
- 团队能在指定时间做完高精度内容、多人、UGC、开放世界或大量剧情。
- Demo 一定能拿到愿望单、投资、发行兴趣或媒体传播。
- 某参考游戏的成功可以直接迁移。

## VOI 判断

只有当调研会改变以下结果时，才值得在文档阶段引入外部调研：项目是否继续、方向选择、范围决定、优先级排序、Go/No-Go 或停止条件。不改变行动的调研标"可选学习项"。

上游 proposal-writer 的其余内容（商业提案/独立游戏档案框架、pitch 质量门等）面向对外文档，功能 GDD 工作流不使用，不随包携带。
