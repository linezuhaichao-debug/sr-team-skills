# sr-gdd-human 使用卡：出功能 GDD 成稿（主线成稿步）

**什么时候用**："写策划案"、"出 GDD"、"出一份给开发团队看的可读版 GDD"、"基于××出合并定稿"——主线里它是**成稿步**：入口产出（sr-concept 设计稿 / sr-analysis 复刻规格 / 旧案）在这里第一次落成完整的规则+界面 GDD。

```
/sr-gdd-human 基于 英雄改造v0.2.xlsx 出合并定稿
```

与 sr-gdd-ai 的分工：本 skill 承担**前置撰写纪律**（资产盘点、VOI 取舍确认、上游映射不遗漏、证据优先级、不编造），只留设计结果——不生成配置契约（表由策划自建）、不写证据/拍板编号/裁决表/台账/治理引用。重点保证功能规则（条件/动作/结果/边界齐全且一句话可读）与界面流程（每个界面 ASCII 线框图 + 逐条 UE 规则表）详细到位。

两条硬约束：**不把配置数值当规则**（正文只写机制，配置数字改一遍正文应一字不用改）、**只保留当前口径**（不写新旧对照）。

**Human Gate**：`approve` / `approve_with_conditions` / `revise` / `reject`（无 request_missing_evidence，缺材料流程内已问）。

**产出**（`sr_workspace\`）：`proposals\<主题>_<日期>.md` + 极简决策记录。

主线位置：**成稿是主线第 2 步，先于 sr-gdd-ai**——入口产出经本 skill 出可读版成稿，交 `/sr-config` 落配置，最后由 sr-gdd-ai 把成稿+配置变更整合成带溯源的定稿。也可单独使用；成稿后可交 sr-gdd-html 出宣讲页。
