# 新表与配置测试数据

本文件只在任务新建运行时表时读取。新建工作簿和在既有工作簿中新增运行时表都适用；既有表的字段或记录变更不自动补测试数据。

## 新表产出

每张新运行时表必须具备：

- 五行字段定义，数据从第 6 行开始；
- 已确认的字段顺序、主键和索引；
- 唯一的 `INDEX` 输出映射；
- 配置说明和字段批注——字段批注是硬性交付物：每个含枚举、单位、格式、引用、约束或边界语义的字段，其第 1 行中文名单元格必须写批注（填写规则/取值/引用或约束/最小示例），批注随字段 change 一并进入 change set 并读回验收；
- 至少一条配置测试记录。

没有依据的正式业务数值保持“待正式填写”。配置测试数据是用于程序自测和联调的可运行数据，不代表最终正式数值。

## 测试数据契约

测试数据写入新运行时表第 6 行起的数据区，与正式记录同构，并进入正常导出链路。每条测试记录必须在 change set 中以独立 change 表达：

```yaml
fixtures:
  - fixture_id: FIX-001
    change_id: CHG-010
    sheet_id: SHEET-001
    start_row: 6
    record_key: {}
    values: {}
    fixture: true
    non_production: true
    replacement_required: true
    fixture_coverage:
      enum_values: []
      condition_branches: []
      codec_shapes: []
    reference_checks: []
    primary_key_unique: true
```

要求：

- 每张新运行时表至少一条测试记录；
- 主键在目标表和本次全部测试记录中唯一；
- 必填字段具有合法值；
- 枚举、单位、边界、空值和 codec 通过契约校验；
- 引用 ID 必须来自当前 `config_root` 中真实存在的记录，并保存工作簿、工作表、字段和键值定位；
- 跨表测试数据使用同一套可解析主键；
- 无法取得真实引用 ID 或无法证明主键唯一时，产生 blocker；
- 测试数据只能验证已确认契约，不能反向新增字段或改变枚举、单位、codec、引用和约束。

符合已确认 schema 的测试数据无需逐行再次确认，可使用 `basis: confirmed_schema` 自动批准；它仍必须进入 change set 并参与全量读回。

## 覆盖范围

`fixture_coverage` 必须列出实际覆盖的枚举值、条件分支和 codec 形态，不能只写“已覆盖”。每张表至少包含一条可运行的正常路径记录；用户或策划规则明确要求的分支必须覆盖。未要求覆盖的全部枚举值不自动扩张为测试范围。

配置说明必须：

- 声明当前列出的记录用于程序自测和联调，不代表最终正式数值；
- 列出每张表的测试记录主键；
- 说明正式数值定档后需要替换测试记录；
- 明确测试数据会进入正常导出链路。

完成条件：每张新运行时表都有达到声明覆盖范围的合法测试数据；全部测试主键、引用和 `fixture: true` 标记可追溯。
