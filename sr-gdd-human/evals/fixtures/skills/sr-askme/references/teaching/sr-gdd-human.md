# sr-gdd-human 使用卡：出人类可读版 GDD

**什么时候用**："出一份给开发团队看的可读版 GDD"、"定稿只留规则不要过程"、"基于××出合并定稿"。

```
/sr-gdd-human 基于 神话宝库四版GDD 出合并定稿
```

与 sr-gdd-ai 的分工：**只留设计结果**——不生成配置契约（表由策划自建）、不写证据/拍板编号/裁决表/台账/治理引用。重点保证功能规则（条件/动作/结果/边界齐全且一句话可读）与界面流程（每个界面 ASCII 线框图 + 逐条 UE 规则表）详细到位。

两条硬约束：**不把配置数值当规则**（正文只写机制，配置数字改一遍正文应一字不用改）、**只保留当前口径**（不写新旧对照）。

**Human Gate**：`approve` / `approve_with_conditions` / `revise` / `reject`（无 request_missing_evidence，缺材料流程内已问）。

**产出**（`sr_workspace\`）：`proposals\<主题>_<日期>.md` + 极简决策记录。

适合在 sr-gdd-ai 定稿后出"执行版"，或材料充分时直接一步出可读版；成稿后可交 sr-gdd-html 出宣讲页。
