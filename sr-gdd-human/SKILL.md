# Skill: sr-gdd-human
# 功能 GDD 工作流（主线成稿步，SR-GDD-Human）

## 功能说明

**唯一输出：功能 GDD（过程层工作文档）**。以 `resources/templates/feature-gdd-human.md` 为形态基准，产出**供审核确认的中间产物**——本 skill 是主线上的**成稿步**：上游材料在这里第一次落成完整的功能 GDD，设计内容（规则、界面）与决策过程（来源、设计核、假设/风险台账、治理引用）都留在这里，随后 `/sr-config` 据此落配置表，`sr-gdd-ai` 吸收其结果章整合成干净定稿。**本 skill 是设计内容的唯一撰写地**：定稿发现设计问题会按修订路由退回这里定向修订。与 `sr-gdd-ai` 的差异：

- **不生成配置契约章节**——本文档不建配置表、不定义配置字段、**规则行不出现配置字段名**（含 snake_case 与"配表名.字段名"式写法）；配置由策划在建表阶段自行完成。
- **两层结构**——**结果章**（功能意图/玩家动词/核心循环/功能规则/界面流程/范围门/埋点/验证计划/验收标准/交接清单/数值待定项）只呈现设计结果：规则是什么、界面长什么样、怎么验收，遵守人类可读性纪律；**过程章**（模板 §0：来源材料清单、概念种子、设计核候选与已选、玩家承诺契约、假设台账、风险台账、待确认问题、未支持声明、治理引用）承载决策留痕，供审核确认与 sr-gdd-ai 溯源，按台账格式正常填写，不适用结果章的可读性纪律。过程章只写**结构性留痕**（台账表格、一句话条目），对话过程、中间草稿、被否掉的候选论证不上文档。
- **重点章节**：
  - §功能规则（R1–Rn）：详细、全面、程序可实现粒度（条件/动作/结果/边界齐全），但**人类可读性优先**——每条规则用一句自然语言说清"谁在什么条件下做什么、得到什么、边界是什么"，禁止夹配置字段名、禁止来源标注噪音；未定数值统一写"（参考值 X，待定）"，文末"数值待定项"只列待定项名称。
  - **规则编号两级制**：只保留规则组编号 R1、R2…（一个规则组 = 一个主题）；**组内不再编 R1.1/R1.2 式小号**，组内每条规则直接用自然语言陈述（表格或条目形式均可）。需要交叉引用时引用到规则组级（如"见 R2"）；确实需要指明组内某条时用"R2 存量不足"这类"组号+规则名"写法，不引入新的编号层级。
  - §用户体验与界面流程：**每个界面一张 ASCII 线框图**（布局/控件/UE 标注）+ **逐条编号的 UE 规则表**（交互/反馈/边界）+ 界面清单总览 + 界面流程 text 图 + 状态机（如适用）+ 全局交互规范。每个界面单独出线框图（层级总图代替不了单界面图）；线框图注释使用单义措辞，避免被读出第二种排版。
- **边界纪律**：功能归属要划清——通用组件（如货币详情弹窗）、其它系统既有界面（如英雄详情页）不属于本功能时，在界面清单下用引用声明"不属于本活动/本功能"，本功能只写触发关系，不展开其内部设计。
- **数值纪律（不得把配置数值当作规则）**：配置表随时会改，**文档不出现具体数值**——门槛值、次数、价格、概率、奖励内容、ID/号段、时间窗口等一律在正文写成机制表述（"每 N 次""达到主城等级门槛""概率合计 100%"），**不写具体测试数字**，需要落数时统一写"（参考值 X，待定）"；文末"数值待定项"**只列待定项名称，不回填设计稿参考值、初值或任何具体数字**（该节只有编号列可以出现数字）。判定标准：把配置表里所有数字任意改一遍，全文应当**一字不用改**。
- **只保留当前口径（不留历史）**：文档只写**当前生效**的规则与口径，**不保留被取代的旧说法、不做新旧对照、不写"本次改动/上版还写的是××"** 这类过程叙述；确需提醒的废弃口径，只在文末"已废弃口径（如需追溯）"**用一句话列出（不列表格、不做对比）**，正文一律按当前口径书写。判定标准：正文不存在任何"曾经/原先/旧稿/变更前"式表述，读者无需知道历史即可正确实现。
- **不留教学性内容**：模板（`resources/templates/feature-gdd-human.md`）里的写作提示只是给撰写时看的，落稿前一律删除——成稿中不得残留模板的 HTML 注释或"写法要求"式引用块。
- **不编造缺失的上游材料**——缺什么就列最小缺失清单，由人决定补不补（见第 2 步）。**证据优先级**：`配置表 > 客户端代码 > 策划文档/UE > 推断`；材料间冲突以高优先级来源为准，正文按胜出口径书写，冲突与理由入 §0.5 假设台账或 §0.7 待确认问题（按影响选）。推断内容在正文标 `【推断】`，不得写成确定事实；**市场/付费/增长类断言无证据时不得写入**。

## 使用方法

```
/sr-gdd-human <主题或材料路径>
```

或直接说人话，例如"把这份复刻规格整理成功能 GDD（人类可读版）"、"基于英雄改造v0.2.xlsx 出一份人类可读的合并定稿"。

## 无输入时的行为

裸调用时按 `../sr-askme/references/bare-invocation.md` 的共用纪律执行（说明输入、停下等待，不自行找题）。本 skill 收集：

1. **主题**：要写哪个功能的 GDD。
2. **上游材料**（有就给路径，没有就明说没有）：sr-concept 功能设计稿 / sr-analysis 复刻规格（或其 GDD 交接 JSON）/ 旧策划案 / 脑图 / 体验记录 / 界面参考截图 / 相关决议。材料薄不阻塞，最低输入是主题 + 能支撑规则粒度的描述；缺的取舍会以极简方式向用户确认（只问"选哪个"，不带证据论述）。

## 路径约定

文中 workspace 路径以 `<SR_WORKSPACE>` 占位书写，运行时从 `../sr-askme/config.local.json` 解析（不存在或字段为空时，先按 `../sr-askme/SKILL.md` 的首次配置引导收集并写入）。产出与材料路径沿用团队 workspace 约定（`proposals\` 存 GDD，`decisions\` 存决策记录），与 `sr-gdd-ai` 一致。

## 执行流程

### 第 0 步 · 载入项目语境

读 `../sr-askme/references/sr_project_context.md`，遵守其中的写作约束（中文写作、术语与项目代码命名一致、多语言键用项目通用格式、gdd 不出现代码/技术选型/程序实现细节、区分 RPG 战斗与 SLG 战斗）。数值铁律在本 skill 下的执行方式：**正文不把配置数值当规则**（机制表述 + "参考值 X，待定"，配置字段名只作指代），并**只写当前口径**（不留新旧对照与已废弃说法）。
完成判据：已读完该文件。

### 第 1 步 · 资产盘点

列出用户提供的与 workspace 已有的上游材料，盘点范围：入口产出（sr-concept 功能设计稿 / sr-analysis 复刻规格及其 GDD 交接 JSON `analysis\sr-gdd-handoff_*.json`）、旧策划案、脑图/提纲、体验记录/竞品笔记、界面/UE 草稿、相关决议记录（`decisions\`）、配置表（.xlsx）。只盘点信息充分性，**本文档不生成"来源材料清单"章节**。

**上游含交接 JSON / 功能设计稿 / 复刻规格时**：其中已拍板的取舍直接作为本文档的既定口径（不重新问、不写拍板过程）；其"配置项预测"留给 sr-config/sr-gdd-ai 消化，本 skill 只在"数值待定项"体现待定名称。
完成判据：材料清单（内部备忘）。

### 第 2 步 · 关键取舍确认（极简决议问答）

只对**会改变规则走向**的取舍问用户（VOI 门：不改变规则走向的缺失标"可选"，不阻塞、不追问），每条给候选 + 推荐 + 一句话理由，请用户拍板。**不带证据论述、不展开分析过程**——用户要的是结果文档，不是论证。材料充分时跳过本步。缺什么就列最小缺失清单，由人决定补不补；不编造缺失材料，把未知写成确定事实比缺一节更危险。
完成判据：关键取舍已获用户拍板（或有意识的默认选择已告知用户）。

### 第 3 步 · 撰写

以 `resources/templates/feature-gdd-human.md` 为章节骨架与形态基准撰写（结构、详细度、可读性均以它为准）。

撰写要求：

- **规则章（详细度核心）**：规则组（R1、R2…）下每条规则 = 条件/动作/结果/边界齐全，一句话可读；规则组间职责单一（一个主题一个组）；需要交叉引用时引用到组级（如"见 R2"），**不编组内小号**（禁止 R1.1/R1.2 式编号）；数值**不写进规则**（机制表述 + "参考值 X，待定"），**规则行不得出现配置字段名**（含 snake_case 与"配表名.字段名"式写法），要指代时写字段的中文含义而非字段名本身。
- **界面章（详细度核心）**：每个界面一张 ASCII 线框图（含布局、控件、UE 标注）+ UE 规则表（逐条编号 UE1…，含边界与状态）；界面清单总览表；完整操作序列 text 图；状态机（如适用）；全局交互规范表。线框图注释避免歧义。嵌套的解锁/失败分支/默认回退行为用**层级缩进列表**表达，不塞进大表格。
- **只写当前口径**：正文一律按当前生效规则书写，不出现"曾经/原先/旧稿/变更前/本次已改"等历史性表述；被取代的旧口径如需追溯，只在文末"已废弃口径（如需追溯）"用**一句话**列出（不列表格、不做对比）。
- **过程章（模板 §0）**：来源材料清单、概念种子、设计核候选与已选、玩家承诺契约、假设台账、风险台账、待确认问题、未支持声明、治理引用——在成稿阶段一并填写（设计取舍发生时同步留痕，不事后补造）；输入为复刻规格/旧案且无设计核取舍时，§0.3 写"继承自上游"即可，不强凑。
- **结果章不写**：证据编号、拍板编号、裁决表、配置契约、模板教学性提示（HTML 注释与"写法要求"式引用块）——这些属于过程或后续环节；来源与取舍信息归 §0。
- **要写**：数值待定项（文末集中，**只列待定项名称**，不回填参考值/初值/具体数字）、验收标准（AC，可执行断言）、范围门、埋点信号、验证计划、交接清单。
- **上游材料映射（不遗漏）**：入口产出与旧案的全部设计信息必须经过思考后落到对应章节——功能详细 → 功能规则，界面/UE → 界面章，范围与不做项 → §范围门，验收 → §验收标准；已拍板取舍直接成为规则口径；材料里映射不了的差异点，用"待确认：<事项>"一句话留痕。成稿后逐项核对：上游每个设计结论在文中都有落点，不遗漏、不只在对话里提一句。
- 术语全文一致（同一系统一个名字，如"英雄招募"不与"招募电台"混用）。
完成判据：模板每一节都有实质内容或显式标注；无过程性内容残留；正文与规则行均无配置字段名；全文无具体数值；无模板教学提示残留；**上游设计信息逐项核对无遗漏**。

### 第 4 步 · 自查（人类可读性，限结果章）

成稿后通读**结果章**（§1–§12），按以下清单自查并修正（§0 过程章按台账完整性自查：无占位符残留、与正文结论一致）：

- [ ] 每条规则读一遍：非策划/程序的人能否一句话复述？
- [ ] 规则章是否只有组级编号（R1、R2…），无 R1.1/R1.2 式组内小号？
- [ ] 结果章有无来源标注、证据编号、拍板编号、"待配表"散落正文？（来源与取舍应归 §0 过程章）
- [ ] 规则行是否完全没有配置字段名（含 snake_case、"配表名.字段名"式写法）？
- [ ] **配置数值纪律**：把配置表所有数字任意改一遍，全文是否**一字不用改**？（全文不得出现具体数值，机制表述 + "参考值 X，待定"；"数值待定项"只列待定项名称，不回填参考值/初值）
- [ ] **只保留当前口径**：正文是否有"曾经/原先/旧稿/变更前/本次已改"式历史表述？（应全部清除，废弃口径只留在文末一句话追溯项，且不是表格）
- [ ] 成稿是否已删除模板的教学性提示（HTML 注释、"写法要求"式引用块）？
- [ ] 每个界面是否都有线框图 + UE 表？线框图注释有无歧义？
- [ ] 未定数值是否都集中在"数值待定项"？
- [ ] 术语是否全文一致？
- [ ] 通用组件/其它系统界面是否已声明"不属于本功能"？
- [ ] 上游材料的设计结论是否逐项落进正文（无遗漏、无只停留在对话里）？
- [ ] 推断内容是否都标了 `【推断】`，无把未知写成确定事实？
完成判据：自查清单全部通过；不过关则修订后复查。

### 第 5 步 · Human Gate

向用户呈现成稿并等待选择：

```
approve / approve_with_conditions / revise / reject
```
完成判据：用户已从上述选项中明确选择其一；选择前不写决策记录。

（本 skill 不设 request_missing_evidence 选项——缺材料在第 2 步已问过。）用户 approve 后按 `../sr-askme/references/decision-recording.md` 写一份极简决策记录（status 映射同 sr-gdd-ai：approve→accepted）。

## 与 sr-gdd-ai 的关系

主线顺序是**先 human 后 ai**（见 sr-askme 教学主线）：本 skill 是**成稿步**——基于入口产出（sr-concept 设计稿 / sr-analysis 复刻规格 / 旧案）出**过程层工作文档**：设计结果人类可读，决策过程完整留痕；`/sr-config` 据此落配置表；`sr-gdd-ai` 吸收本成稿的结果章，整合成**没有思考决策过程的干净定稿**交给程序。设计内容的唯一撰写地在本 skill——定稿发现设计问题会携带修订点清单退回这里，定向修订后重新流过下游。

- 本 skill 承担**前置撰写纪律**：资产盘点、VOI 取舍确认、上游材料映射不遗漏、证据优先级与不编造——成稿的质量门在这里。
- `sr-gdd-ai` 承担**整合与留痕**：配置契约、证据溯源、治理引用、五选项 Human Gate；它也可以直接从旧案/配置表起步（跳过 human 版），但主线位置是整合定稿。
