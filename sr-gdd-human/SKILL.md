# Skill: sr-gdd-human
# 功能 GDD 工作流（人类可读版，SR-GDD-Human）

## 功能说明

**唯一输出：功能 GDD（人类可读版）**。以《神话宝库_合并定稿_20260828》为形态范本，产出面向内部团队的功能开发文档。与 `sr-gdd-ai` 的差异：

- **不生成配置契约章节**——本文档不建配置表、不定义配置字段、规则里不引用配置字段名；配置由策划在建表阶段自行完成。
- **不写过程性内容**——不保留来源材料清单、证据编号（E001…）、拍板编号（T01/C5/D3…）、裁决表、假设台账、风险台账、未支持声明、治理引用。文档只呈现**设计结果**：规则是什么、界面长什么样、怎么验收。
- **重点章节**：
  - §功能规则（R1–Rn）：详细、全面、程序可实现粒度（条件/动作/结果/边界齐全），但**人类可读性优先**——每条规则用一句自然语言说清"谁在什么条件下做什么、得到什么、边界是什么"，禁止夹配置字段名、禁止来源标注噪音；未定数值统一写"（参考值 X，待定）"并在文末"数值待定项"集中列出。
  - **规则编号两级制**：只保留规则组编号 R1、R2…（一个规则组 = 一个主题）；**组内不再编 R1.1/R1.2 式小号**，组内每条规则直接用自然语言陈述（表格或条目形式均可）。需要交叉引用时引用到规则组级（如"见 R2"）；确实需要指明组内某条时用"R2 存量不足"这类"组号+规则名"写法，不引入新的编号层级。
  - §用户体验与界面流程：**每个界面一张 ASCII 线框图**（布局/控件/UE 标注）+ **逐条编号的 UE 规则表**（交互/反馈/边界）+ 界面清单总览 + 界面流程 text 图 + 状态机（如适用）+ 全局交互规范。禁止只画一张层级图敷衍；线框图中的注释不得产生歧义（如不得出现会被误读为"按档位分行排版"的写法）。
- **边界纪律**：功能归属要划清——通用组件（如货币详情弹窗）、其它系统既有界面（如英雄详情页）不属于本功能时，在界面清单下用引用声明"不属于本活动/本功能"，本功能只写触发关系，不展开其内部设计。
- **数值纪律（不得把配置数值当作规则）**：配置表随时会改，**文档规则不绑定任何配置数值**——门槛值、次数、价格、概率、奖励内容、ID/号段、时间窗口等一律在正文写成机制表述（"每 N 次""达到主城等级门槛""概率合计 100%"，或直接写字段中文名如"主城等级门槛/创角天数门槛"），**不写具体测试数字**，需要落数时统一写"（参考值 X，待定）"并集中在文末"数值待定项"。判定标准：把配置表里所有数字任意改一遍，正文规则应当**一字不用改**。
- **只保留当前口径（不留历史）**：文档只写**当前生效**的规则与口径，**不保留被取代的旧说法、不做新旧对照、不写"本次改动/上版还写的是××"** 这类过程叙述；确需提醒的废弃口径，只在文末"已废弃口径（如需追溯）"用一句话列出，正文一律按当前口径书写。判定标准：正文不存在任何"曾经/原先/旧稿/变更前"式表述，读者无需知道历史即可正确实现。

## 使用方法

```
/sr-gdd-human <主题或材料路径>
```

或直接说人话，例如"基于神话宝库四版 GDD 出一份人类可读的合并定稿"、"把这份复刻规格整理成功能 GDD（人类可读版）"。

## 无输入时的行为

调用时未带任何主题或材料（裸 `/sr-gdd-human`），不得自行扫描 workspace 找题目。先用一段话向用户说明需要什么，并停下等输入：

1. **主题**：要写哪个功能的 GDD。
2. **上游材料**（有就给路径，没有就明说没有）：旧策划案 / 复刻规格 / 体验记录 / 界面参考截图 / 配置表（.xlsx）/ 相关决议。材料薄不阻塞，最低输入是主题 + 能支撑规则粒度的描述；缺的取舍会以极简方式向用户确认（只问"选哪个"，不带证据论述）。

## 路径约定

文中 workspace 路径以 `<SR_WORKSPACE>` 占位书写，运行时从 `../sr-askme/config.local.json` 解析（不存在或字段为空时，先按 `../sr-askme/SKILL.md` 的首次配置引导收集并写入）。产出与材料路径沿用团队 workspace 约定（`proposals\` 存 GDD，`decisions\` 存决策记录），与 `sr-gdd-ai` 一致。

## 执行流程

### 第 0 步 · 载入项目语境

读 `../sr-askme/references/sr_project_context.md`，遵守其中的写作约束（中文写作、术语与项目代码命名一致、多语言键用项目通用格式、gdd 不出现代码/技术选型/程序实现细节、区分 RPG 战斗与 SLG 战斗）。数值铁律在本 skill 下的执行方式：**正文不把配置数值当规则**（机制表述 + "参考值 X，待定"，配置字段名只作指代），并**只写当前口径**（不留新旧对照与已废弃说法）。
完成判据：已读完该文件。

### 第 1 步 · 资产盘点（内部进行，不写入文档）

列出用户提供的与 workspace 已有的上游材料。**本文档不生成"来源材料清单"章节**——盘点只为确认信息充分性。
完成判据：材料清单（内部备忘）。

### 第 2 步 · 关键取舍确认（极简决议问答）

只对**会改变规则走向**的取舍问用户，每条给候选 + 推荐 + 一句话理由，请用户拍板。**不带证据论述、不展开分析过程**——用户要的是结果文档，不是论证。材料充分时跳过本步。
完成判据：关键取舍已获用户拍板（或有意识的默认选择已告知用户）。

### 第 3 步 · 撰写

以 `resources/templates/feature-gdd-human.md` 为章节骨架撰写。**形态范本：`<SR_WORKSPACE>\proposals\神话宝库_合并定稿_20260828.md`**（结构、详细度、可读性以它为基准；workspace 无此文件时以其结构描述为准，不阻塞）。

撰写要求：

- **规则章（详细度核心）**：规则组（R1、R2…）下每条规则 = 条件/动作/结果/边界齐全，一句话可读；规则组间职责单一（一个主题一个组）；需要交叉引用时引用到组级（如"见 R2"），**不编组内小号**（禁止 R1.1/R1.2 式编号）；数值**不写进规则**（机制表述 + "参考值 X，待定"），配置字段名只作指代（如"主城等级门槛/创角天数门槛"）而不携带具体数值。
- **界面章（详细度核心）**：每个界面一张 ASCII 线框图（含布局、控件、UE 标注）+ UE 规则表（逐条编号 UE1…，含边界与状态）；界面清单总览表；完整操作序列 text 图；状态机（如适用）；全局交互规范表。线框图注释避免歧义。
- **只写当前口径**：正文一律按当前生效规则书写，不出现"曾经/原先/旧稿/变更前/本次已改"等历史性表述；被取代的旧口径如需追溯，只在文末"已废弃口径（如需追溯）"用一句话列出。
- **不写**：来源清单、证据/拍板编号、裁决表、配置契约、假设/风险台账、治理引用。
- **要写**：数值待定项（文末集中）、验收标准（AC，可执行断言）、范围门、埋点信号、验证计划、交接清单。
- 术语全文一致（同一系统一个名字，如"英雄招募"不与"招募电台"混用）。
完成判据：模板每一节都有实质内容或显式标注；无过程性内容残留；正文无配置字段名引用。

### 第 4 步 · 自查（人类可读性）

成稿后通读一遍，按以下清单自查并修正：

- [ ] 每条规则读一遍：非策划/程序的人能否一句话复述？
- [ ] 规则章是否只有组级编号（R1、R2…），无 R1.1/R1.2 式组内小号？
- [ ] 有无来源标注、证据编号、拍板编号、"待配表"散落正文？
- [ ] 有无配置字段名出现在规则行？
- [ ] **配置数值纪律**：把配置表所有数字任意改一遍，正文是否**一字不用改**？（正文不得出现具体测试数值，机制表述 + "参考值 X，待定"）
- [ ] **只保留当前口径**：正文是否有"曾经/原先/旧稿/变更前/本次已改"式历史表述？（应全部清除，废弃口径只留在文末一句话追溯项）
- [ ] 每个界面是否都有线框图 + UE 表？线框图注释有无歧义？
- [ ] 未定数值是否都集中在"数值待定项"？
- [ ] 术语是否全文一致？
- [ ] 通用组件/其它系统界面是否已声明"不属于本功能"？
完成判据：自查清单全部通过；不过关则修订后复查。

### 第 5 步 · Human Gate

向用户呈现定稿并等待选择：

```
approve / approve_with_conditions / revise / reject
```

（本 skill 不设 request_missing_evidence 选项——缺材料在第 2 步已问过。）用户 approve 后按 `../sr-askme/references/decision-recording.md` 写一份极简决策记录（status 映射同 sr-gdd-ai：approve→accepted）。

## 产出规范

| 产出 | 路径（workspace 下） |
|------|------|
| 功能 GDD（人类可读版） | `proposals\<主题>_<日期>.md` |
| 决策记录（极简） | `decisions\decision_<主题>_<日期>.json` |

日期格式 `YYYYMMDD`。目录不存在时创建。

## 与 sr-gdd-ai 的关系

- `sr-gdd-ai`：完整流程（证据溯源、配置契约、治理引用、五选项 Human Gate），适合需要可追溯性的正式立项。
- `sr-gdd-human`：**结果导向**的轻量流程，省略溯源与配置章节，换取可读性与撰写速度；上游材料的过程信息消化在撰写中，不留痕。两者可先后使用：先用 sr-gdd-ai 做带证据的规格定稿，再用本 skill 出给开发团队看的可读版。
