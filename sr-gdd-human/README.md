# sr-gdd-human

功能 GDD 工作流（人类可读版）：以《神话宝库_合并定稿_20260828》为形态范本，产出只含设计结果的功能开发文档——不生成配置契约、不留证据/拍板/治理等过程性内容，重点保证功能规则详细且可读、界面流程完整到位。

用法：`/sr-gdd-human <主题或材料路径>`

三条硬约束：

1. **全文不出现具体数值**——只写机制，规则行不得出现配置字段名（含 snake_case、"配表名.字段名"式写法）；未定数值用"参考值 X，待定"占位，文末"数值待定项"只列待定项名称、不回填初值。把配置表数字任意改一遍，全文应一字不用改；
2. **只保留当前口径**——不写新旧对照与"本次已改"式历史表述，废弃口径只在文末用一句话追溯（不列表格）；
3. **不留教学性内容**——模板里的写作提示（HTML 注释、"写法要求"式引用块）落稿前删除。

评测：`evals/` 下有 skill-up 评测套件（7 条用例），跑法与判定口径见 `evals/README.md`。

与 `sr-gdd-ai`（完整溯源版）的区别见 SKILL.md「与 sr-gdd-ai 的关系」。
