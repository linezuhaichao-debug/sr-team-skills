# 宣讲 HTML 生成工具包 · 先读

> 来源：AI_SR 项目交互交付流程（SR）中「01_宣讲会交付.html」的生成规范与工具，2026-09-10 整理。
> 用途：给交互/策划同事独立生成同规格的宣讲 HTML。本包是**阅读与工具参考**，不是技能安装包。

## 这个 HTML 是什么

交互交付三件套里的 **01_宣讲会交付**：给评审/下游**人读**的图文宣讲——按玩家流程逐界面一节、左侧完整界面截图、右侧逐控件规则，能边看图边讲。它**不是**给策划 AI 回写用的（那是 02 MD 的职责），所以内容红线是：**只放最终规则，禁止出现确认编号、用户原话、"拍板/已确认"等过程性信息**。

## 怎么用（最快路径）

1. 读 `01_宣讲会模板.md`（10 分钟）——内容边界、页面结构、冒烟清单全在里面；
2. 把截图放进 `截图/` 文件夹（Figma 目标 Frame 按 2x 导出，或原始分辨率界面图）；
3. 照 `生成脚本/content_示例.json` 的格式填你的内容（章节/图片文件名/规则块）；
4. 运行：`python 生成脚本/gen_01.py --content 生成脚本/content_示例.json --img-dir 截图 --out 01_宣讲会交付.html`（Python 3.8+，无第三方依赖）；
5. 按模板末尾的**轻量视觉冒烟清单**过一遍（破图/溢出/文字墙/布局失衡/导航五项），有问题改 JSON 重跑。

## 三条最容易被忽视的规矩

1. **参考优先级**：模板 > 你自己当前项目用户指定的样式 > 最近通过校验的历史样例——别自由发挥结构；
2. **长章节让左图吸顶**（sticky）：右侧规则长、左图一屏就滚完 = 布局失衡，宣讲时图就不在了（样例里 `.shot{position:sticky;top:40px}` 已处理，生成脚本自带）；
3. **规则块化**：右栏必须是"控件名小标题 + 规则正文"的块，禁止 `<br>` 连排成文字墙；生成脚本的 JSON 里一个 `["控件名", "文本"]` 就是一块。

## 边界说明

- 排版间距/字号等视觉参数模板**不设死**，按当轮审美定；拿不准时参考合格样例；
- 本包不含 AI_SR 的交付校验链（verify 脚本/manifest/打包规范）——那是正式交付包的事，你们只用生成 HTML 的话用不到；
- 若后续想把这套规范作为技能装进你们的 Agent 平台，找 AI_SR 侧走 `cross-agent-skill-sync` 做直连源安装，不要拷贝文件夹当技能装（会跟源头漂移）。
