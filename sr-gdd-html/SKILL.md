# 评审宣讲 HTML 工作流（SR-GDD-HTML）

## 功能说明

**唯一输出：评审宣讲 HTML（单文件自包含）**。把一份功能 GDD **定稿**（`<SR_WORKSPACE>\proposals\<主题>_<日期>_定稿.md`；`sr-gdd-ai` 主线 `active` 定稿，`provisional` 工作版亦可）重排成"能边看图边讲"的单页 HTML：按玩家流程逐界面一节、左栏完整界面截图、右栏逐控件规则块，截图 base64 内嵌、无任何外部依赖，可直接投屏、可直接外发。

渲染规格与 AI_SR 交互交付的 `01_宣讲会交付.html` 同源：固定验收模板见 `resources/toolkit/01_宣讲会模板.md`，通用生成器见 `resources/toolkit/生成脚本/gen_01.py`（原样内置，无第三方依赖，Python 3.8+）。

**本 skill 不生产设计结论**。它只做呈现层的重排——规则、数值、边界全部来自源定稿；源定稿没写的一律标"待定"，不替策划补规则、不臆造数值。**只接定稿**：还没有定稿时走 `sr-gdd-human`（写成稿）→ `/sr-config`（落配置）→ `sr-gdd-ai`（整合定稿）；定稿之后的改动走 `/sr-gdd-fix`。

### 参考优先级（不要自由发挥结构）

1. `resources/toolkit/01_宣讲会模板.md`（固定验收模板，内容边界与页面结构的唯一权威）
2. 用户当轮指定的参考样式
3. 两者皆无时：`examples/合成示例/01_评审宣讲_示例.html`（形态基准）

排版间距/字号等视觉参数模板**不设死**，但结构、内容边界、图片承载方式不得改。

### 内容红线（越线即返工）

- **只放最终规则**：定稿口吻的交互规则、流程、界面状态与关键界面图；
- **禁止过程性信息**：确认编号（Q1/Q2…）、用户原话、"拍板 / 已确认 / 跟推荐"等过程措辞一律不出现——这些属于决策记录与 GDD 的职责，不属于给人讲的宣讲页；
- **不放文本 ID 清单**（那是交互回写文档的职责）；
- 每个界面章节是"讲这个界面"的最小完整单元：**讲解者只看本节即可开口**。

### 图片红线

- 图片一律 `data:image/...;base64,` 内嵌，保证单文件可独立打开、单独发送不丢图；
- **禁** `https://` 外链图（会过期、离线丢失）；
- **禁** `./assets/` 等散装资源目录——"HTML + 资源目录"没有例外，需要连目录才能打开的稿子只能算非正式过程文档；
- 图外标注（字母/引线）**默认关闭**，未获当轮明确要求时交付干净原图；启用时按 `resources/toolkit/双栏版式参考_outside-callout-module.md` 执行（含 `#F02864` / 2px / 实线 / 禁斜线等细则）。

## 使用方法

本 skill 是**用户调用型**（frontmatter `disable-model-invocation: true`）：只能由人输入 `/sr-gdd-html` 触发，agent 不会自动接手，也不进入面向模型的技能目录。

```
/sr-gdd-html <定稿路径或主题>
```

例如"把《英雄升级功能优化_20260902_定稿》出成评审会用的 HTML"、"这份定稿出一版宣讲页"。

## 无输入时的行为

裸调用纪律见 `../sr-askme/references/bare-invocation.md`。本 skill 收集：

1. **源定稿**：要出 HTML 的那份**定稿** md（路径，或主题名由我从 `<SR_WORKSPACE>\proposals\` 下定位 `_定稿.md`）；
2. **宣讲范围**（可选，默认按定稿界面清单全出）：本场只讲哪几个界面/状态；
3. **截图目录**（可选，没有就说没有，无图界面走指路占位框，不阻塞）。

用户补齐后再从第 0 步开始。

**输入守卫**：源文件不是**定稿**时停下，说明本 skill 只接功能 GDD 定稿，并指出该走哪一步——还没有定稿：`/sr-gdd-human` → `/sr-config` → `/sr-gdd-ai`；已有定稿但要改内容：`/sr-gdd-fix`。**不静默加工非定稿材料**——成稿、体验报告、复刻规格、评审意见、会议纪要等一律不做。

## 路径约定

`<SR_WORKSPACE>` / `<SR_PROJECT>` 取自 `../sr-askme/config.local.json`；字段缺失、为空或路径失效时运行 `/sr-askme` 补齐；成组安装见 `../sr-askme/SKILL.md` §四。

本 skill 自身资源以**相对路径**引用（`resources/toolkit/...`、`tools/lint_content.py`），保证 skill 目录可整体搬迁。

## 执行流程

### 第 0 步 · 载入项目语境

读 `../sr-askme/references/sr_project_context.md`，遵守其中的数值铁律与写作约束（中文、术语与项目代码命名一致、gdd 不出现代码/技术选型细节、区分 RPG 战斗与 SLG 战斗）。

数值铁律在本 skill 下的执行方式：**宣讲页沿用源定稿 的数值口径**——源定稿 写"参考值 X，待定"的照写，写 `配表名.字段名` 的照写；本 skill 不新增、不换算、不补全任何数值。
完成判据：页内每个数值都能在源定稿 中找到同一写法——不新增、不换算、不补全。

### 第 1 步 · 输入确认

定位源定稿，先读顶部 `status`：`active` 按正常宣讲流程处理；`provisional` 允许继续抽取，但 `content.json` 的 `footer` 必须显式写"工作版，非正式定稿"；`blocked` 直接停止并报告阻断原因；**其余取值**（成稿 `draft`、没有 `status` 的旧文档）说明这不是定稿，按「输入守卫」停下并给出去路，不据文件名猜测。随后确认三件事，缺一即问用户，不自行假设：

| 项 | 内容 |
| --- | --- |
| 源文件 | **定稿**路径 + 版本/日期（同名多版本时以用户指定为准，不默认取最新） |
| 宣讲范围 | 全量界面，还是本场只讲某几个界面/状态 |
| 截图目录 | 有无现成界面图；没有则确认走指路占位框 |

同时清点源定稿的可用结构：界面清单（`§5.0` 之类）、逐界面章节、UE 规则表、规则组（R1…Rn）、全局交互规范、范围门、数值待定项。

**完整性门（重要）**：源定稿若缺"界面清单"——即没有任何一节能支撑"一个界面一节"的宣讲结构——**停下向用户报告**。这是**定稿自身**的缺口，不是在宣讲页里凑合的事：先走 `/sr-gdd-review`（确认问题）或 `/sr-gdd-fix`（补界面章节）把定稿补全，再回来出宣讲页。
完成判据：源文件、源定稿 `status`、宣讲范围、截图目录四项明确；**源文件已确认是定稿**（`active`，或已标注的 `provisional`），非定稿已停下并给出去路；`provisional` 的 `content.json.footer` 已标记为工作版；完整性门有结论。

### 第 2 步 · 结构抽取（定稿 → content.json）

按 `references/content-schema.md` 的字段映射表把定稿重排成 `content.json`。**只搬运，不发明**；映射不了的差异点列出来问用户，不自行决定。规则块写法（块标题用控件名、不带编号、正文按 展示/点击/反馈/异常 组织、禁文字墙）与章节编排（收尾固定三节）见同一文件。


**章节编排**：

1. 逐界面/逐状态节（主体）——按玩家流程排序；
2. 同一界面的通用规则合并到"默认状态"节，其余状态节**只写差异**，不重复；
3. 收尾固定三节（评审会必需，定稿里是表格也要转成规则块）：
   - **全局规则与红线**：跨界面约束 + 全局交互规范（弹窗栈、按钮互斥、返回键、多语言、网络容错、刷新）；
   - **范围门**：纳入（最小可行版本/切片）与**明确排除**各成一块——评审会最容易吵的就是边界；
   - **数值待定项**：把定稿里标"待定"的数值集中成一块，会上一次过完。
4. 埋点信号默认不纳入；用户明确要时再加一节。

**边界纪律**：属于其它系统或通用组件的界面（如获取引导弹窗、别的系统详情页），不展开其内部设计，只写触发关系，并在该节 `guide` 里声明"不属于本功能"。
完成判据：`content.json` 落盘；每个界面清单项都有对应节；无编号残留、无外链、无自造规则。

### 第 3 步 · 截图准备

- 截图目录默认 `<SR_WORKSPACE>\proposals\宣讲素材_<主题>_<日期>\`（用户给了目录就用用户的）；
- 命名 `两位序号_界面名[_状态].png`，与 `content.json` 的 `image` 字段一一对应（大小写、空格严格一致）；
- 截图应为**完整界面**（不裁控件局部），Figma 导出按 2x 或原始分辨率；
- 缺图的界面：`image` 填 `null` + 补 `guide`，左栏渲染指路占位框——**不阻塞交付**；
- **全篇无截图要停下来确认**：当整份定稿一张界面图都没有（常见于只有 ASCII 线框图的定稿），左栏会全是占位框、右栏全是规则，形成"左空右满"的失衡版式；第 4 步的 lint 会报 `全篇无截图` 警告，**这是必须处置的信号，不得静默交付**。两条去路由用户选：① 补界面截图后再出（推荐，宣讲效果差别很大）；② 明确接受"以讲规则为主"的纯文字版，并在页脚标注"本页无界面截图"。
- 缺图**不是**用网络图凑数的理由：禁止外链、禁止从别处抓图。
完成判据：`content.json` 中每个 `image` 在截图目录内可命中（或已改为 `guide` 占位）；若全篇无截图，已获用户明确选择。

### 第 4 步 · 红线与结构校验

**必须先跑校验、再生成**（生成器只做字段与图片存在性校验，不查内容红线）：

```bash
python <skill>/tools/lint_content.py --content content.json --img-dir <截图目录>
```

校验内容：必需字段、id/num 唯一性与格式、有图或有指路（不留空）、图片存在性、外链检测，以及上文「内容红线」与「图片红线」的词表检查；同时给出文字墙等视觉风险警告。
**红线命中 = 失败**，修 `content.json` 后重跑，不得带警告交付。
完成判据：`lint_content.py` 退出码 0，且无 warning 残留。

### 第 5 步 · 渲染

```bash
python <skill>/resources/toolkit/生成脚本/gen_01.py --content content.json --img-dir <截图目录> --out "<输出.html>"
```

生成器产出单文件自包含 HTML（截图 base64 内嵌）。生成器报 `[FAIL]` 一律先修源数据，不手改 HTML 输出——**HTML 是派生物**，任何内容修订都回到 `content.json` 重跑。
完成判据：输出 HTML 落盘，生成器打印节数与图片数符合预期。

### 第 6 步 · 轻量视觉冒烟（每次必检）

五项每次必过，**并以无头浏览器实际渲染确认**——只读 HTML 源码不算通过：

- [ ] 无破图（每张图解码成功）
- [ ] 无横向溢出 / 重叠
- [ ] 无大段文字墙（规则已块化，工具会点名超阈值的规则正文）
- [ ] 无布局失衡（长章节滚动时左图是否过早滚出视口——模板要求左图吸顶）
- [ ] 章节导航锚点可用（逐个锚点能跳到对应节）

首选内置检查器（自动判定上面五项 + 整页截图，Node ≥ 22，无第三方依赖，自动拉起本机 Chrome/Edge），并顺带守住"图片必须 data: 内嵌"的承载红线：

```bash
node <skill>/tools/smoke_check.mjs --html "<输出.html>" --out smoke.png
```

**退出码非 0 即不予交付。** Node 不可用时的降级路径：

```bash
# Chrome / Edge 无头截图（路径含中文时先复制到 ASCII 路径）
chrome --headless=new --disable-gpu --window-size=1440,6000 --screenshot=smoke.png "file:///<输出.html 的绝对路径>"
```

**无论哪条路径，最后都要人眼过一遍截图**（工具判"结构没坏"，判不了"讲得清不清楚"）。发现问题改 `content.json` 重跑；修复后重检。无需全页面逐屏验收。
完成判据：五项全过，且截图已目视复核（不是"看起来应该没问题"）。

### 第 7 步 · Human Gate

向用户呈现**宣讲页 HTML 与自查结果**，等待选择：

```
approve / revise / resupply_screenshots / reject
```
完成判据：用户已从上述选项中明确选择其一；选择前不写决策记录。

（本 skill 不设 `request_missing_evidence`——缺材料在第 1/3 步已问过。）

- `revise`：按意见改 `content.json` 重跑第 4–6 步；
- `resupply_screenshots`：换/补截图后重跑第 3–6 步；
- `approve`：按 `../sr-askme/references/decision-recording.md` 写决策记录，`status` 映射 `approve→accepted`、`reject→rejected`、`revise / resupply_screenshots→proposed`。

## 产出规范

| 产出 | 路径（`<SR_WORKSPACE>\` 下） |
| --- | --- |
| 评审宣讲 HTML（交付物，外发用） | `proposals\<主题>_宣讲_<日期>.html` |
| content.json（可复跑源，随 HTML 留档） | `proposals\<主题>_宣讲_<日期>.content.json` |
| 决策记录 | 按 `../sr-askme/references/decision-recording.md` 落盘（`decisions\` 下） |

日期格式 `YYYYMMDD`；目录不存在时创建。`content.json` 与 HTML **成对留档**：别人拿到 HTML 想改一处文案，不必重新读一遍 GDD。
